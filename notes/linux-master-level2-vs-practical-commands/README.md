# 리눅스 검색 클릭 × 리눅스마스터 출제기준 대조 노트

블로그 jjeongil.tistory.com에 리눅스 관련 검색어로 들어온 90일 클릭을 KAIT 리눅스마스터 출제기준 영역에 나눈 집계와, 그 분류 규칙·출제기준 대응·시험 일정 확인 기록이다.

## 파일

| 파일 | 내용 |
|---|---|
| `classify_linux_queries.py` | 검색어를 리눅스 관련 여부와 영역으로 분류해 영역별 집계 CSV를 만드는 스크립트 |
| `areas.csv` | 영역별 검색어 수·노출·클릭과 출제기준 대응 항목, 합계 |
| `site-wide-terms.csv` | 리눅스로 좁히지 않은 사이트 전체 기준의 실무 검색어 묶음 5개(검색어 수·클릭) |
| `usermod-append-repro.md` | `usermod -G`에서 `-a`를 뺐을 때 보조 그룹이 교체되는 재현 절차 |
| `usermod-append-repro.txt` | 위 재현의 출력(grep 결과는 실제, 명령 줄은 옮겨 적음) |

## 수집 방법과 기준일

- 데이터: 이 블로그의 Google Search Console 검색어×페이지 90일 데이터, 2026년 11월 15일 생성.
- 입력 형식: `{"queries": {"검색어": [{"page", "impressions", "clicks", ...}]}}`. GSC 원본 행이라 이 노트에는 넣지 않는다.
- 절차: (1) 리눅스 필터 정규식에 맞는 검색어만 남긴다 → (2) 영역 규칙을 위에서부터 차례로 대 보고 처음 맞은 영역 하나에 넣는다 → (3) 영역별로 검색어 수·노출·클릭을 더한다. 어느 규칙에도 맞지 않으면 「미분류」.
- 결과: 리눅스 관련 검색어 2,348개, 노출 112,233, 클릭 4,419. 연결된 글은 385편.
- 사용: `python3 classify_linux_queries.py --input <GSC JSON> --output areas.csv`

## 한계

- **분류 순서가 결과를 바꾼다.** 규칙은 부팅 → 사용자·계정 → 에디터 → 파일 → 권한 → 시스템 정보 → 디스크 → 프로세스 → 패키지 → 셸 → 네트워크 → X 윈도 → 로그 순으로 대 보고 처음 맞은 영역 하나에만 넣는다. 예를 들어 "사용자 권한"처럼 두 영역에 걸치는 검색어는 앞선 사용자·계정으로 간다.
- **계정 규칙이 넓다.** `user`·`root`·`sudo`·`su `가 들어간 검색어는 대부분 계정 영역으로 잡혀, 권한·패키지 등 다른 영역의 검색어 일부가 여기에 섞여 있다.
- **미분류가 크다.** 어느 규칙에도 맞지 않은 검색어가 597개, 클릭 436이다. 규칙에서 빠진 표현(유저 생성의 일부 변형, `nc` 같은 짧은 명령 등)이 섞여 있다.
- **PHP 버전 검색어는 의도적으로 넣었다.** 리눅스 필터에 `php 버전|php version|php버전`을 직접 넣었다. 리눅스 셸에서 PHP 버전을 확인하는 글로 들어오는 검색어라서다. 이 검색어는 「버전·메모리 등 시스템 정보」로 분류되며, 이 영역 클릭 699의 상당 부분을 차지한다.
- **클릭은 검색 수요 전체가 아니다.** 이 블로그에 어떤 글이 있고 몇 위에 있는지에 따라 클릭이 달라진다. 예를 들어 권한 영역의 대표 검색어는 상위 10위 안에 있어서, 1~3위 영역보다 클릭이 적게 잡힌다.
- **프로세스 영역 노출은 이상치 하나에 끌린다.** 이 영역 노출 38,723 가운데 약 3.7만이 cron을 설명하는 영어 검색어 하나에서 나왔고, 그 검색어의 클릭은 0이다. 그래서 본문 표와 그림은 노출이 아니라 클릭으로 비교했다.
- **사이트 전체 묶음은 이 스크립트로 다시 만들지 않는다.** `site-wide-terms.csv`의 5개 묶음은 글 기획 때 리눅스 필터 없이 사이트 전체 검색어를 키워드로 묶어 센 값이다. 리눅스 영역 집계와 일부 겹친다(특히 PHP 버전).
- 출제 비중(공개 기출의 영역별 문항 수)은 이 대조에 들어 있지 않다. 이 노트의 대조는 「출제기준 영역 × 이 블로그 클릭」이다.
