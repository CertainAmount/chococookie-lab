# 개발 신입 공고 자격증 언급 수집 엔진

고용24 채용정보에서 개발 직무 신입·경력무관 공고를 모아, 정보처리기사·정보처리산업기사·SQLD·리눅스마스터·정보보안기사를 공고가 어디에 어떻게 적었는지(자격 면허 칸 필수/우대/기타, 본문 언급, 언급 없음) 센다. 자격증 글 여러 편과 갱신에서 다시 돌려 기준일별로 쌓는다.

| 파일 | 내용 |
|---|---|
| `collect.py` | 수집기. 검색어 13개 × 경력(신입, 관계없음)으로 목록을 읽고, 개발 직무로 보이는 공고의 상세를 읽는다 |
| `analyze.py` | 분류·집계. 본문을 읽을 수 있는 개발 직무 공고만 대상으로 자격증별 언급을 나눈다 |
| `postings-YYYY-MM-DD.csv` | 공고 1건 1행: 출처, 회사명, 제목, 모집 직종, 경력, 우대조건, 기타 우대사항, 자격 면허 칸, 자격증별 언급 여부, 정보처리기사 언급 앞뒤 문맥 |
| `summary-YYYY-MM-DD.csv` | 출처 묶음 × 자격증별 집계 |
| `search-totals-YYYY-MM-DD.csv` | 검색어·경력 조건별 검색 건수와 수집 건수 |

## 실행

```
python3 collect.py --out . --delay 1.5 --max-detail 2000
python3 analyze.py postings-YYYY-MM-DD.csv
```

고용24 공개 화면만 읽는다(로그인 없음, robots.txt에서 막지 않은 경로). 요청 사이 1.5초를 둔다. 채용 담당자 연락처는 상세 본문에서 잘라 내 저장하지 않는다. 이전 CSV를 덮어쓰지 않고 기준일을 붙여 쌓는다.

|---|---|---|---|---|---|

## 분류 기준

- **분석 대상:** 고용24 화면에서 공고 본문이 1,500자 이상 보이는 공고. 사람인·잡코리아·캐치·인크루트 연계 공고는 고용24 화면에 모집 직종 같은 요약만 있고 본문이 없어 제외했다(원문 포털을 직접 수집하지 않는다).
- **개발 직무:** 고용24 직접 공고는 「모집 직종」이 소프트웨어·웹·앱 개발 직종인 것. 디자이너·강사·하드웨어·사무 직종은 뺐다. 연계 공고는 제목에 개발 직무 말이 있는 것.
- **자격 면허 칸:** 고용24 직접 공고에는 「자격 면허」 칸이 있고, 기업이 「필수 ○○ / 우대 ○○ / 기타 문장」으로 적는다. 정보처리기사가 「필수」 뒤에 오면 필수, 「우대」 뒤면 우대(자격 칸), 「기타」 문장 안이면 우대(자격 칸 기타)로 셌다.
- **본문 언급:** 자격 면허 칸에는 없고 우대사항 문단 등 본문에만 이름이 나온 경우.
- 「관련 자격증 우대」처럼 이름 없는 문구는 따로 표시만 하고 특정 자격 언급으로 세지 않았다.

## 한계

- 표본이 작다(분석 대상 61건). 비율보다 "어디에 몇 건"으로 읽는다. 회차를 쌓아 늘린다.
- 고용24에 직접 공고를 올리는 회사는 중소기업 비중이 크다. 대기업·플랫폼 기업 공고는 대부분 연계 공고라 본문을 읽지 못했다.
- 공공기관(알리오·나라일터·클린아이) 개발 공고는 수집일에 고용24 연계 목록에 거의 없었다(알리오 0건). 공공 쪽 가점은 이 엔진 밖에서 각 기관 공고 원문으로 본다.
- 검색어 기반이라 제목·본문에 그 말이 없는 개발 공고는 빠질 수 있다.
